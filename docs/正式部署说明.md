# 翻牌钟简化版 · 正式部署说明

**写给负责服务器部署的同事。** 部署脚本在 `deploy/` 目录里，改好配置后一条命令跑完。

## 一、系统组成

| 部分 | 说明 |
|---|---|
| 服务 | 一个 Node.js 进程（Express + WebSocket），同时提供网页、接口和实时通道 |
| 遥控页 | `https://域名/`：手机网页，所有操作都在这里完成 |
| 大屏页 | `https://域名/tv/`：电视安卓外壳（APK）加载这个地址 |
| 接口 | `https://域名/api/...`；健康检查用 `GET /api/time` |
| 实时通道 | `wss://域名/ws`：大屏和手机都会长时间保持连接 |
| 数据 | 服务器上 `FLAPCLOCK_DATA_DIR` 目录下的 JSON 文件（赛事、屏幕、盲注方案）；**没有数据库** |

整个服务只有一个进程，数据保存在这一个进程的内存和磁盘文件里，所以**只能部署一个实例**，不能多开做负载均衡。

## 二、服务器要求

- **系统**：Linux，已装 Docker 和 Docker Compose v2。
- **必须已经有一个占着 80/443 的边缘网关容器。** 本项目**不自己发布 80/443**，而是接入那个容器所在的 docker 网络，由它按容器名反代进来。当前这台服务器上这个容器叫 `poker-timer-web`，它的 vhost 放在 `/opt/edge/conf.d/`、证书放在 `/opt/edge/certs/`。
  - 如果目标服务器上还没有这个边缘网关，先部署 poker-timer-platform，它会把这两处挂载和 include 装好。
- **独立的（子）域名**：例如 `flapclock.example.com`。页面用到的都是根路径（`/`、`/tv/`、`/api`、`/ws`），**不能挂在其他网站的子目录下**。
- **HTTPS 证书，并且必须被安卓 6 信任**：
  - 正式版 APK 只加载 HTTPS 地址，证书有问题就直接拒绝。
  - 安卓 7.1 以下的系统不认 Let's Encrypt 的根证书，所以**不要用 Let's Encrypt**。
  - 建议使用阿里云或腾讯云提供的、由 DigiCert 签发的证书。
  - 部署后的自检脚本会检查这一点。
- **ICP 备案**：手机多半是用微信扫码打开遥控页的，未备案的域名在微信里会被拦截或弹出风险提示。
- **时间同步**：服务器开启 NTP（chrony 或 systemd-timesyncd 即可）。所有屏幕都以服务器时间为准，时间要稳定。

**执行部署的那台电脑**需要：Node.js（用来跑 `deploy/deploy.mjs`）、`ssh` 和 `scp`，以及到服务器的 ssh 免密登录。还没配免密的话，在 poker-timer-platform 仓库里跑一次 `node deploy/setup-ssh.mjs`（用密码装公钥，只需一次）。

## 三、端口与网络

- **容器内监听 `18630`，不向宿主机发布任何端口。** 外部完全访问不到它，只有同一个 docker 网络里的边缘网关能按容器名 `flapclock-app` 访问。
- **选 18630 的原因**：它避开了 80/443、3000、3306、5432、6379、8000～8090、8443、8888、9000～9200、27017 这些常见服务端口，也低于 Linux 的临时端口范围（32768 起）。
- **改端口要同时改两处**：`/opt/flapclock/.env` 里的 `FLAPCLOCK_PORT`，以及 `/opt/edge/conf.d/<域名>.conf` 里的 `proxy_pass`。只改一处边缘会 502。
- 容器接入的网络由 `.env` 里的 `EDGE_NETWORK` 决定，默认 `current_default`（poker-timer 的 compose 项目网络）。**这个网络必须已存在**，否则容器起不来；`deploy.mjs` 会提前检查并给出明确提示。

## 四、部署步骤

```bash
# 1. 在仓库根目录，准备好部署脚本的配置
cp deploy/.env.example deploy/.env
#    至少填这几项：
#      DEPLOY_HOST=root@<服务器IP>
#      DOMAIN=<你的域名>
#      EDGE_CONTAINER=poker-timer-web
#    deploy/.env 已被 .gitignore 忽略，真实值不会进版本库。

# 2. 放好证书（腾讯云免费 DV 证书，Nginx 格式）
#    把 <域名>.pem 和 <域名>.key 放进 deploy/certs-local/
#    目录不对的话用 deploy/.env 里的 CERTS_DIR 指定。
#    证书还没准备好也能先部署，脚本会跳过边缘 vhost 安装并明确提示。

# 3. 一条命令部署
node deploy/deploy.mjs
```

`deploy.mjs` 依次做这几件事，每步都有输出：

1. 打包源码 → `deploy/.ship`，压成 `deploy/.ship.tgz`
2. 预检服务器（ssh 通不通、docker 和 compose 在不在、边缘网络存不存在）
3. 上传并解压到 `/opt/flapclock/src`
4. 在服务器上构建镜像并起容器（首次要拉 `node:22-alpine`、装依赖，几分钟）
5. 安装边缘 vhost 和证书到 `/opt/edge/`
6. **自动跑两套自检**：服务器侧 `deploy/check-server.sh`，公网侧 `deploy/check.sh https://<域名>`

自检全部通过才算部署完成。公网自检会检查：

- 接口、遥控页、大屏页都能访问。
- 大屏页返回的是真页面，而不是「前端尚未构建」的纯文本（后者状态码同样是 200，但电视打开是白屏）。
- 实时通道的握手返回 101。如果失败，多半是边缘 vhost 里 `Upgrade` 和 `Connection` 两个请求头没配好。
- 证书链不是 Let's Encrypt，并打印证书到期时间。

常用参数：

| 参数 | 用途 |
|---|---|
| `--check` | 只自检，不动服务器 |
| `--no-build` | 跳过镜像构建（只重新起容器 / 装边缘配置） |
| `--no-edge` | 不碰 `/opt/edge`（只更新应用本身） |
| `--repair-edge` | 只修边缘扩展点，见第九节 |
| `--host root@1.2.3.4` | 临时指定服务器，覆盖 `deploy/.env` |
| `--certs-dir D:\certs` | 临时指定本地证书目录 |

## 五、服务器上的目录

| 路径 | 内容 |
|---|---|
| `/opt/flapclock/src` | 解压后的源码（`deploy.mjs` 每次部署会覆盖它） |
| `/opt/flapclock/.env` | 运行参数。首次部署时由脚本从 `deploy/flapclock.env.example` 生成，**之后不会被覆盖**，改过的值会保留 |
| `/opt/flapclock/data` | 数据目录（由 `FLAPCLOCK_DATA_DIR` 指定），挂进容器的 `/data` |
| `/opt/edge/conf.d/<域名>.conf` | 边缘 vhost，由 `deploy.mjs` 从 `deploy/edge/` 的模板生成（模板里的占位域名会替换成 `deploy/.env` 里的 `DOMAIN`） |
| `/opt/edge/certs/<域名>.pem` `.key` | 边缘证书，权限分别是 644 / 600 |

## 六、正式版 APK

部署好域名之后，打包正式版 APK：

```bash
cd tv-android
# 先放好签名密钥：flapclock-release.jks 和 keystore.properties（单独交接，不在代码仓库里）
./gradlew assembleProdRelease -PtvOrigin=https://flapclock.example.com/tv/
# 产物：app/build/outputs/apk/prod/release/app-prod-release.apk
```

打包需要 JDK 17 和安卓 SDK，详见 `tv-android/README.md`。

正式版只能加载上面这个地址。**域名一旦定下来就不要再改**，换域名就要重新打包，所有电视都要重装。

## 七、数据、备份与恢复

- **数据位置**：`/opt/flapclock/data`（宿主机目录，挂进容器的 `/data`）。服务每次写文件都是先写临时文件再替换，不会出现写了一半的文件。
- **备份**：直接复制整个目录即可，建议每天备份一次，例如：

  ```bash
  tar czf /backup/flapclock-$(date +%F).tgz -C /opt/flapclock data
  ```

- **恢复**：
  1. `docker stop flapclock-app`
  2. 用备份覆盖 `/opt/flapclock/data`。
  3. `docker start flapclock-app`（或跑一次 `node deploy/deploy.mjs --no-build`，它会重新起容器并跑自检）

## 八、升级与回滚

- **升级**：在仓库根目录重新跑一次 `node deploy/deploy.mjs`。它会重新打包、上传、构建镜像、起容器，并跑完两套自检。
  重启期间大屏会继续按本机时钟计时，连上之后自动恢复同步。
- **回滚**：
  - 只是镜像有问题：改 `/opt/flapclock/.env` 里的 `FLAPCLOCK_TAG` 指回上一个 tag，再跑 `node deploy/deploy.mjs --no-build`。
  - 代码有问题：把仓库切回上一个版本，重新跑 `node deploy/deploy.mjs`。
- **建议**：升级前先备份一次数据（见第七节）。数据结构没有变化时可以直接回滚。

## 九、边缘扩展点被冲掉时

poker-timer 每次发布会用**它发布包里**的 compose 和 `nginx.conf` 重建 `poker-timer-web` 容器。如果那次发布的包没带上边缘扩展点（`/opt/edge` 的两处挂载和 include），本项目就会突然 502，而它自己的容器看上去一切正常。

在服务器上跑 `bash /opt/flapclock/src/deploy/check-server.sh` 可以直接指出这种情况。修复：

```bash
node deploy/deploy.mjs --repair-edge
```

一条命令修回来。脚本会自动判断要不要重建边缘容器（重建会让现有站点约 1~2 秒不可用，能只 reload 时脚本只做 reload）。

## 十、安全提示（必读）

目前**不需要登录**：任何能打开这个网址的人，都能控制比赛和屏幕。这是现阶段的产品决定，部署到公网时请至少采取下面的措施：

- **限制访问来源**：只允许门店的出口 IP 访问。在 `/opt/edge/conf.d/<域名>.conf` 的 `location /` 和 `location /ws` 里加上 `allow 门店IP; deny all;`，注意电视也要从这些 IP 访问。改完执行：

  ```bash
  docker exec poker-timer-web nginx -t && docker exec poker-timer-web nginx -s reload
  ```
