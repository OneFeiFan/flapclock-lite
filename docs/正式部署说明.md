# 翻牌钟简化版 · 正式部署说明

写给负责服务器部署的同事。配置模板都在 `deploy/` 目录里，按本文的步骤改好域名、路径、端口即可。

## 一、系统组成

| 部分 | 说明 |
|---|---|
| 服务 | 一个 Node.js 进程（Express + WebSocket），同时提供网页、接口和实时通道 |
| 遥控页 | `https://域名/`：手机网页，所有操作都在这里完成 |
| 大屏页 | `https://域名/tv/`：电视安卓外壳（APK）加载这个地址 |
| 接口 | `https://域名/api/...`；健康检查用 `GET /api/time` |
| 实时通道 | `wss://域名/ws`：大屏和手机都会长时间保持连接 |
| 数据 | `DATA_DIR` 目录下的 JSON 文件（赛事、屏幕、盲注方案）；**没有数据库** |

整个服务只有一个进程，数据保存在这一个进程的内存和磁盘文件里，所以**只能部署一个实例**，不能多开做负载均衡。

## 二、服务器要求

- **系统**：Linux。以下命令以 Ubuntu 或 Debian 为例。
- **Node.js**：20 LTS 或更高版本。
- **Nginx**：负责 HTTPS 和转发，实时通道也通过它转发。
- **独立的（子）域名**：例如 `flapclock.example.com`。页面用到的都是根路径（`/`、`/tv/`、`/api`、`/ws`），**不能挂在其他网站的子目录下**。
- **HTTPS 证书，并且必须被安卓 6 信任**：
  - 正式版 APK 只加载 HTTPS 地址，证书有问题就直接拒绝。
  - 安卓 7.1 以下的系统不认 Let's Encrypt 的根证书，所以**不要用 Let's Encrypt**。
  - 建议使用阿里云或腾讯云提供的、由 DigiCert 签发的证书。
  - 部署后的自检脚本会检查这一点。
- **ICP 备案**：手机多半是用微信扫码打开遥控页的，未备案的域名在微信里会被拦截或弹出风险提示。
- **时间同步**：服务器开启 NTP（chrony 或 systemd-timesyncd 即可）。所有屏幕都以服务器时间为准，时间要稳定。

## 三、端口

- **服务默认监听 `127.0.0.1:18630`**，只给本机的 Nginx 转发用，**不需要、也不应该对外开放**。对外只开放 Nginx 的 80 和 443 端口。
- **选 18630 的原因**：它避开了 80/443、3000、3306、5432、6379、8000～8090、8443、8888、9000～9200、27017 这些常见服务端口，也低于 Linux 的临时端口范围（32768 起）。
- **部署前先确认没有被占用**：`ss -ltnp | grep 18630`，没有输出就说明可以用。
- **如果被占用了**：
  1. 在环境变量文件里改 `PORT`，比如改成 18631。
  2. 把 Nginx 配置里两处 `127.0.0.1:18630` 改成同一个端口。
- **端口被占用时服务会直接退出**，并给出提示，不会悄悄改用别的端口。

## 四、部署步骤

```bash
# 1. 运行用户和目录
sudo useradd --system --home /opt/flapclock --shell /usr/sbin/nologin flapclock
sudo mkdir -p /opt/flapclock /var/lib/flapclock /etc/flapclock
sudo chown flapclock:flapclock /var/lib/flapclock

# 2. 放代码（解压源码包，或者 git clone），交给运行用户，然后安装依赖并构建网页
cd /opt/flapclock
sudo chown -R flapclock:flapclock /opt/flapclock
sudo -u flapclock npm run setup
sudo -u flapclock npm run build

# 3. 运行参数
sudo cp deploy/flapclock.env.example /etc/flapclock/flapclock.env     # 按需修改 PORT
sudo nano /etc/flapclock/flapclock.env

# 4. 后台服务
sudo cp deploy/flapclock.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now flapclock
sudo systemctl status flapclock          # 应为 active (running)
journalctl -u flapclock -n 20            # 启动日志里能看到监听地址

# 5. Nginx：改好域名、证书路径、端口后放进去
sudo cp deploy/nginx.conf.example /etc/nginx/conf.d/flapclock.conf
sudo nano /etc/nginx/conf.d/flapclock.conf
sudo nginx -t && sudo systemctl reload nginx

# 6. 自检
./deploy/check.sh https://flapclock.example.com
```

自检脚本会检查以下几项，全部通过才算部署完成：

- 接口、遥控页、大屏页都能访问。
- 实时通道的握手返回 101。如果失败，多半是 Nginx 里 `Upgrade` 和 `Connection` 两个请求头没有配好。
- 证书链不是 Let's Encrypt，并打印证书到期时间。

## 五、正式版 APK

部署好域名之后，打包正式版 APK：

```bash
cd tv-android
# 先放好签名密钥：flapclock-release.jks 和 keystore.properties（单独交接，不在代码仓库里）
./gradlew assembleProdRelease -PtvOrigin=https://flapclock.example.com/tv/
# 产物：app/build/outputs/apk/prod/release/app-prod-release.apk
```

打包需要 JDK 17 和安卓 SDK，详见 `tv-android/README.md`。

正式版只能加载上面这个地址。**域名一旦定下来就不要再改**，换域名就要重新打包，所有电视都要重装。

## 六、数据、备份与恢复

- **数据位置**：都在 `DATA_DIR` 目录下（默认 `/var/lib/flapclock`）。服务每次写文件都是先写临时文件再替换，不会出现写了一半的文件。
- **备份**：直接复制整个目录即可，建议每天备份一次，例如：

  ```bash
  tar czf /backup/flapclock-$(date +%F).tgz -C /var/lib flapclock
  ```

- **恢复**：
  1. `sudo systemctl stop flapclock`
  2. 用备份覆盖 `DATA_DIR`。
  3. `sudo systemctl start flapclock`

## 七、升级与回滚

- **升级**：
  1. 更新 `/opt/flapclock` 里的代码。
  2. 如果依赖有变化，执行 `npm run setup`。
  3. 执行 `npm run build`，然后 `sudo systemctl restart flapclock`。

  重启大约需要 1 秒，期间大屏会继续按本机时钟计时，连上之后自动恢复同步。
- **回滚**：换回上一个版本的代码，重新构建并重启。数据格式没有变化时，可以直接回滚。
- **建议**：升级前先备份一次数据。

## 八、安全提示（必读）

目前**不需要登录**：任何能打开这个网址的人，都能控制比赛和屏幕。这是现阶段的产品决定，部署到公网时请至少采取下面一种措施：

- **限制访问来源**：只允许门店的出口 IP 访问，在 Nginx 的 `location /` 和 `location /ws` 里加上 `allow 门店IP; deny all;`。注意电视也要从这些 IP 访问。
- **重新启用登录**：管理口令加手机名称的登录功能已经做好，保存在 Git 历史的提交 `350337e` 里（服务端的 `auth.js` 及相关改动），有需要时可以找回启用。
